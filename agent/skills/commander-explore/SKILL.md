# Explore possibilities

Start from Mike's spark or the existing project vision and relevant notes. Flavor-first, mechanic-first and commander-first are all valid; unresolved choices may stay open.

Offer a few genuinely different possibilities: the table moment, how the engine works, likely friction and a satisfying ending. Compare commanders as mascot, engine or both, including dependence and threat perception—not popularity alone. Separate the desired experience from any particular implementation.

Use [search](../commander-search/SKILL.md) to discover supporting cards and adjacent mechanisms beyond the existing pool. Research should test whether each direction has real support, not merely verify remembered examples. Mark unresolved card claims honestly.

When a direction has a playable draft, use [goldfish](../commander-goldfish/SKILL.md) to test its development or engine before committing to it. Exploration, list edits and testing can alternate within the existing draft scope.

Exploration is provisional, not a new commitment. Keep only consequential live ideas or abandoned-direction reasons in project notes; a passing idea needs neither a new deck nor a document. Review-ready candidate lists follow [ManaBox workflow](../../docs/manabox-workflow.md); coherent list changes use [refine](../commander-refine/SKILL.md).

When Mike wants to establish or revise the project's intent, use [the vision interview](../commander-vision-doc/SKILL.md). This exploration skill cannot edit `vision.md` or override its approval boundary.
